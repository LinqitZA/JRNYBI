## Session 62 (2026-06-01): Feature #218 — "Explain this number" LLM endpoint

### Feature #218: 'Explain this number' button on KPI cards and chart points — PASSING

Added the full backend + frontend stack so a user can click an "Explain"
icon on a KPI card v2 and get a 2-4 sentence plain-English summary
generated by Anthropic Claude.

Backend
-------
- NEW: redash/explain.py — pure service module (no Flask deps)
  * normalise_payload(): whitelist allowed keys (metric_label, metric_value,
    comparison_*, delta_abs, delta_pct, threshold_label, time_range,
    top_contributors capped at 10, extra_context, query_id, visualization_id),
    coerce metric_value/comparison_value/delta_* to float, truncate string
    fields at 200 chars (defence-in-depth against prompt injection).
  * SYSTEM_PROMPT pins Claude to provided-data-only, no future predictions,
    no invented entities, 2-4 sentences active voice no markdown.
  * build_user_prompt(): deterministic rendering — numbers normalised via
    _fmt_number, delta_pct converted to percent ONCE before display so the
    LLM doesn't double-scale.
  * cache_key(): sha256 over canonical (sorted-keys, no whitespace) JSON →
    "explain:cache:<hex>". Same payload from any user in the cluster hits.
  * get_cached / store_cached: Redis GET/SET with EXPLAIN_CACHE_TTL_SECONDS;
    bytes are decoded; transient redis errors log + cache-miss instead of
    failing the request.
  * check_rate_limit(): per-user per-hour bucket = INCR + EXPIRE 3700s.
    Returns (allowed, count). Fail-open when redis is down.
  * call_anthropic(): POSTs {model, max_tokens, system, messages:[{role:user,
    content:[{type:text, text:build_user_prompt(...)}]}]} to
    settings.EXPLAIN_ANTHROPIC_URL with x-api-key + anthropic-version headers.
    extract_text() concatenates all top-level text blocks and rejects empty
    responses.

- NEW: redash/handlers/explain.py — ExplainResource(BaseResource)
  * POST /api/explain. login_required via BaseResource.
  * 503 when EXPLAIN_FEATURE_ENABLED=false OR ANTHROPIC_API_KEY="" (server
    fully disabled).
  * 400 on schema errors (raised by normalise_payload).
  * 429 when the user's hourly bucket is exhausted; surfaces upstream 429
    from Anthropic as 429 too so the client can back off.
  * 502 on timeouts / 5xx / non-JSON Anthropic responses.
  * On cache hit: skips the LLM call, records {action:"explain",
    cached:true} via existing record_event() pipeline.
  * On cache miss: stores result + records {action:"explain", cached:false,
    rate_count}.
  * Response envelope: {explanation, model, cached, source:{query_id,
    visualization_id}} so the UI can render a "View source data" link.

- EDIT: redash/handlers/api.py — registered ExplainResource at
  /api/explain (org-scoped via add_org_resource).

- EDIT: redash/settings/__init__.py — appended the JRNYBI #218 settings

  * EXPLAIN_FEATURE_ENABLED     (auto: true when key set, false otherwise;

  * EXPLAIN_MODEL               (default "claude-sonnet-4-5-20250929")

  * EXPLAIN_MAX_TOKENS          (default 400)
  * EXPLAIN_TIMEOUT_SECONDS     (default 20)
  * EXPLAIN_CACHE_TTL_SECONDS   (default 3600)
  * EXPLAIN_RATE_LIMIT_PER_HOUR (default 60)

### Feature #216: Anomaly markers on time-series charts (PASSING)
Detect outlier points in a time-series chart, mark them with a red dot, and
overlay a translucent "expected range" band so users see at a glance which
data points fall outside the rolling-mean confidence interval.

Backend (redash/handlers/queries.py + api.py):
- New `/api/queries/<query_id>/anomalies` endpoint (QueryAnomaliesResource)
- Reads `query.latest_query_data` (cached result) so it's a cheap server call,
  no re-execution against the read-replica
- Query params: x (column), y (column), window (default 30, clamped 3-1000),
  threshold (z-score sigma, default 2.0, clamped 0.5-10.0)
- Auto-detects x as first datetime column and y as first numeric column when
  not specified — falls back to first-row inspection heuristics
- Sorts points by x using a robust ISO/date/datetime parser, so window math
  reflects time order even if rows come back unordered
- For each point i computes rolling mean/stddev over the previous `window`
  points (excluding i so the point can't dominate its own band). Flags when
  |z| >= threshold. Direction (above/below) included for tooltip framing.
- Returns: { points: [{index, x, y, z, mean, stddev, direction}],
             bounds: [{x, upper, lower, mean}],
             summary: {count, threshold, window, x_column, y_column, total_points} }
- Requires "view_query" permission + view_only access on the query (same as
  reading the query itself, so RLS / sharing rules are honoured)
- 400 + clear error JSON when query has no cached results or autodetect fails
- Records "compute_anomalies" event for audit trail

Frontend (viz-lib/src/visualizations/chart/...):
- getOptions.ts: defaults `showAnomalies: false`, `anomalyWindow: 30`,
  `anomalyThreshold: 2`. Persisted into the visualization options blob like
  every other chart setting.
- Editor/GeneralSettings.tsx: new "Show anomalies" Section, gated on
  line/area/column charts. Sub-panel reveals window + threshold InputNumbers
  when the toggle is on, with min/max bounds matching the backend clamps so
  the UI can't construct an invalid request.
- plotly/anomalies.ts (NEW): client-side mirror of the backend algorithm.
  buildAnomalyTracesForSeries() returns up to 3 Plotly traces per series:
    1. lower-bound invisible line (base for the band fill)
    2. upper-bound invisible line with fill='tonexty' + translucent red
       fillcolor (rgba(180,35,24,0.12)) — the "expected range" shaded band
    3. anomaly markers — large red circles with white border, mode='markers'
  Each marker carries a `text` entry rendered in the hover tooltip:
    "Anomaly: 3.2σ above the 30-point rolling mean (123.4)"
  Computation uses the same rolling-window-excluding-self algorithm as the
  backend so the visualization matches API output exactly.
- plotly/prepareData.ts: calls appendAnomalyTraces() after the existing
  prepareDefaultData + updateData pipeline for non-pie / non-heatmap charts.
  Pie + heatmap are skipped because time-series anomaly detection is
  meaningless on those visualization types.
- Failsafe: appendAnomalyTraces wraps per-series computation in try/catch
  so a malformed series never breaks the whole chart render. Errors are
  logged to the console but the chart still draws.

### Phase 2 note
Prophet-based richer anomaly detection is called out in the feature spec as
optional/separate. Z-score is the documented Phase 1 implementation and is
what's shipped here. Prophet would land as a follow-up feature with its own
endpoint + library dependency.
